# 翻訳の文章スタイル

English: [TRANSLATION-STYLE.md](TRANSLATION-STYLE.md)

Sakutto は、日本語の文末（`form` の です・ます / だ・である）とは別に、PLaMo 3 Translate へ文章スタイル（フォーマル、ビジネス、カジュアルなど）を渡せます。既定は **標準** です。標準では、この設定が加わる前と同じ PFML3 プロンプトを組み立てます。

この文書は、PFN のモデルカードが実際にサポートしていることと、Sakutto での使い方を記録します。

## モデルが学習している形式

出典: Hugging Face 上の PLaMo 3 Translate モデルカード（`pfnet/plamo-3-translate-2b` など、英語・日本語 README）と、公式の PFML3 プロンプトテンプレート。

PLaMo 3 Translate は翻訳専用です。本番のプロンプトは PFML3 を手で組み立てます。チャットの system メッセージではありません。PFN は、オプションを `apply_chat_template` / PFML3 のフィールドとして渡すよう書いており、**system メッセージにも原文にも書かない**とあります。

| フィールド         | 公式の値                 | 用途                                                                                                                                                                                                     |
| ------------------ | ------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `output` の `lang` | 訳先の言語コード         | 必須。                                                                                                                                                                                                   |
| `output` の `form` | `plain` または `polite`  | 日本語の文末だけ（`target_lang=ja`）。だ・であるとです・ます。これ以外の `form` は文書化されていません。                                                                                                 |
| `context`          | 自由文                   | 「原文を解釈するための参考文脈（前後の文章や場面など）」。PFN の例は、かみの意味を分ける場面（「工作で折り紙を作っています。」）と、ページの種類（「プロジェクト管理ツールのヘルプページです。」）です。 |
| `glossary`         | `source` / `target` の組 | 用語の訳。                                                                                                                                                                                               |

モデルカードの "style" は `form`（常体 / 敬体）を指し、一般的なトーンの列挙ではありません。`form=formal` や `form=casual` はありません。

PLaMo 2 Translate は別のプロンプト（`<|plamo:op|>`）で、`form` も `context` も文書化されていません。Sakutto が載せるのは PLaMo 3 Translate だけです。

## Sakutto での符号化

- **標準**（既定）: 追加の `context` なし。日本語向けの `form=polite` / `form=plain` も含め、以前の既定プロンプトとバイト一致します。
- **標準以外、訳先が `ja` または `en` のときだけ**: 学習済みの `context` に、短い場面・文書の種類の文を書きます。原文が日本語か英語ならその言語、それ以外は訳先の言語です。例: `公式文書です。`、`This is a business document.` PFN の「ページの種類 / 場面」の例に合わせています。「フォーマルに訳せ」「内容を足すな」といった命令文ではありません。
- **それ以外の訳先**: スタイル一覧はありません。言語ごとのスタイル列挙は文書化されておらず、`form` の値を捏造したり、原文に指示を足したりするのは学習された仕組みではありません。
- **`form` とスタイルは独立です。** 日本語の訳先では、です・ますかつカジュアル、だ・であるかつフォーマル、を同じプロンプトに書けます。

載せていないもの:

- 原文や system メッセージへのスタイル指示（本番オプションとしては PFN がどちらも禁じています）。
- モデルが学習していない `form` の値。
- 韓国語・中国語など向けの汎用リスト。`context` 自体はどの言語でも使えますが、公式のスタイルメニューはなく、推測した一覧も結局は場面の文にしかなりません。

「論理的」は対応が一番弱いです。PFN の `context` の例は場面と文書の種類であり、「論点をはっきりさせよ」ではありません。使っている文は「論点と因果関係を述べた説明文です。」であり、書き直せという命令ではありません。意味のずれは、実モデルでの確認が必要です。

## 精度

スタイルは、意味を変えてはならず、内容を落としたり足したりしてはならず、用語集・プレースホルダ・マークアップを壊してはなりません。標準があるのは、既存の利用者のプロンプトを変えないためです。標準以外は語彙の選び方を誤る余地があるので、`pnpm style:eval` があります。

ページ翻訳、選択範囲の翻訳、入力中の翻訳、テキスト翻訳ページは、同じ保存済みの `style` をエンジンへ渡します。

## ローカルでの評価

ユニットテストが見るのはプロンプトのバイト列だけです。PLaMo の重みは読みません。

```sh
llama-server -m plamo-3-translate-0.8b-Q4_K_M.gguf -ngl 99 -c 4096 --port 11501
pnpm style:eval
```

`SAKUTTO_PLAMO_URL` で既定の `http://127.0.0.1:11501` を上書きできます。サーバーが無いときは、各スタイルのプロンプトを表示し、標準が変わっていないことだけ確認して終了コード 0 で終わります。サーバーがあるときは、決めた ja↔en の例文を訳し、各スタイルを標準と比べ、長さの比、数字・固有名・プレースホルダ・用語集の欠落、場面の文が訳文へ漏れることをフラグします。フラグはヒューリスティックであり、誤訳の証明ではありません。表示された訳を読んでください。

このクラウド環境には PLaMo の重みはありません。拡張機能が動いているメンテナの端末にはあります。
