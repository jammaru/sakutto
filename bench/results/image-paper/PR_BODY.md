## Summary / 概要

画像のみで構成された日本語論文 PDF の 2 段組で、左右の OCR テキストが 1 行に結合される問題を修正しました。見出しはそれぞれの段に残り、数式行が段をまたいで合成されることもなくなります。あわせて、ゴミのような OCR ブロックが翻訳要求や訳文オーバーレイに流れないようにし、読者側の速度・進捗計測と先読みを追加しました。

## Changes / 変更内容

- 段組判定: ページ全体の段の位置を先に求め、両段の開始位置とガターを共有する見出しペア（例: `1.はじめに` と `3. ローカル推論基盤`）をタイトル扱いせず 2 行に分割。`5. PDF翻訳とOCR` / `7. OCR評価用の処理構成` や、左段の数式と右段の本文が混ざる行も分割します。
- 日本語の章番号（`1.はじめに`）を章見出しとして認識できるようにし、全幅のタイトル・概要行は従来どおり 1 つのブロックとして保持します。図が入る段も段の判定を乱しません。
- OCR のゴミ（句点だけ、矢印の `V` / `X`、1〜2 文字の改行断片など）は翻訳せず、原文のまま残します。
- 訳文は既存の shrink-to-fit と重なり解消のまま、正しい段の幅でフィットします。
- 書き出し PDF もビューアと同じブロック箱・折り返しを使い、埋め込みフォントの実測幅で再折り返して必要なら縮小します。図のラベルは 1 行のまま箱に収め、文字が段やページの外へはみ出さないようにしました。
- 速度/UX: ページごとの OCR 結果をキャッシュしてスクロール戻りで再実行しないようにし、アイドル時に次のページの取得とテキスト抽出だけを先読みします。翻訳は従来どおりブロック単位で順次描画され、最初の訳文が出る時刻とページ OCR 時間を計測できるようにしました。
- OCR 実行は WebGPU が使える環境では WebGPU EP を試し、使えなければ従来の WASM にフォールバックします（WASM の解像度やモデルは変更なし）。

## How tested / 確認したこと

- `pnpm test`: 223 ファイル / 3199 passed、1 skipped（日本語 2 段組・ノイズブロックと書き出し段組の回帰テストを追加）
- `pnpm lint` / `pnpm typecheck` / `pnpm i18n:check` / `pnpm format:check`: パス
- 実 OCR ベンチ（`bench/pdf/image-only-paper.pdf`）: headless Chromium で 2 ページを描画し、デフォルトの重ね合わせ表示をスクリーンショットで確認。1 ページ目・2 ページ目とも左右の見出しが別の段にあり、段をまたぐ結合はありません。
- `pnpm bench:pdf:scan:ocr -- --variants default-1600`: CER 3.03%（≤ 5%）、crossColumnCovers 0、重なり 0。既存スキャンに回帰なし。

スクリーンショット: `bench/results/image-paper/after-p1.png`, `bench/results/image-paper/after-p2.png`

## Benchmarks / ベンチマーク

画像のみの論文 PDF（2 ページ、CPU の WASM OCR、標準モデル）。翻訳側は決定論的なフェイクエンジンで、描画までの配線時間を測っています。

|                           |  before |   after |
| ------------------------- | ------: | ------: |
| 1 ページ目 初回表示       |  未計測 |   12 ms |
| 1 ページ目 OCR + 翻訳     | 8899 ms | 8674 ms |
| 2 ページ目 初回表示       |   10 ms |    3 ms |
| 2 ページ目 OCR + 翻訳     | 7790 ms | 7912 ms |
| 2 ページ目 段またぎカバー |       2 |       0 |

詳細: `bench/results/image-paper/benchmark.md`, `benchmark.json`。CPU 推論そのものは変えていないため、1 回のコールドページ計測では大きな差は出ていません。キャッシュ・先読み・初回描画は再訪や長文で効きます。

## Notes / 補足

- この実行環境には WebGPU アダプターがなく、WebGPU 側の実測値はありません。WASM フォールバックのみ検証しています。
- OCR の文字誤りに由来する一部の訳語（例: `ローカル` の誤認識）は、モデル側の認識精度の課題として残ります。
